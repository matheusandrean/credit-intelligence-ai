# Security

This repository is designed and maintained as if it were **always public**
(see [`RESPONSIBLE_AI.md`](RESPONSIBLE_AI.md) and the security-first
principle applied throughout development).

## Reporting a Vulnerability

This is a portfolio/educational project. If you find a security issue,
please open a GitHub issue describing the class of problem (avoid posting
exploit details publicly) — see the repository's issue tracker.

## What Is Never Committed

- Real API keys, tokens, or credentials of any kind (`.env` is git-ignored;
  `.env.example` contains variable names only, never values).
- Real personal, financial, or customer data of any kind — every dataset
  in this repository is 100% synthetic, generated by
  `src/data/generate_synthetic_credit_data.py`.
- Generated data files, trained model binaries, or MLflow run artifacts
  (`data/raw/*`, `data/processed/*`, `models/*`, `mlruns/`, `mlflow.db` are
  all git-ignored) — everything is reproducible from code.
- Absolute local machine paths, usernames, or hostnames.
- Notebook outputs that could leak local environment details.

## Secret Hygiene Practices

- `.gitignore` explicitly covers `.env`, `.env.*` (with `.env.example`
  carved out), private keys (`*.pem`, `*.key`, `*.p12`, `*.pfx`),
  `credentials.*`, `secrets.*`.
- `detect-secrets` runs in `.pre-commit-config.yaml` and in CI
  (`.github/workflows/ci.yml`), scanning every commit and pull request.
- `pip-audit` runs in CI to flag known-vulnerable dependencies.
- Before the first push and before every subsequent significant push, the
  diff is manually inspected for secret-shaped strings
  (`api_key`, `token`, `password`, `sk-`, `ghp_`, `github_pat_`, `AKIA`,
  PEM private-key header/footer markers) in addition to the automated
  scanners.

## Application-Level Data Boundaries

- The application only ever processes its own synthetic dataset — no code
  path reads from or writes to a real production database, and none is
  configured by default (see `src/utils/config.py`).
- LLM providers only ever receive what a specific tool call constructs
  (e.g. a portfolio summary, one customer's SHAP values) — never a raw
  environment dump, `.env` contents, or unrelated local files.
- The `query_portfolio` tool only allows read-only `SELECT`/`WITH`
  statements against an in-memory DuckDB view (never a real database
  connection) and rejects `DROP/DELETE/UPDATE/ALTER/INSERT/TRUNCATE/
  CREATE/ATTACH/PRAGMA/...` — see `src/llm/tools/sql_guard.py` and its
  test suite (`tests/unit/test_sql_guard.py`).
- Application logs use structured logging (`structlog`) with a redaction
  processor that masks any key containing `api_key`, `token`, `password`,
  `secret`, or `authorization` (`src/utils/logging.py`).
- The audit log (`reports/audit_log.jsonl`) never stores full tool
  payloads or secrets — only the question, tool names, success/failure,
  cited sources, and model version.

## Docker

- `.dockerignore` excludes `.env`, `.git`, caches, and any credential-shaped
  file from the build context.
- No secret is ever baked into the image via `ENV` or `ARG`; the
  containers read configuration from environment variables supplied at
  `docker run`/`docker compose` time via `.env` (never committed).

## Dependency Security

- Dependencies are declared with minimum version bounds in
  `pyproject.toml`, avoiding unnecessary packages.
- `pip-audit` is run in CI on every push/PR to surface known
  vulnerabilities in the dependency tree.

## GitHub Repository Security

This repository is published with GitHub's default security features
available for public repositories (secret scanning, push protection,
Dependabot alerts) — no repository security setting is weakened.

## Incident Response

If a credential were ever accidentally committed, the response is: stop
further publication, treat the credential as compromised immediately,
revoke/rotate it, remove it from git history with appropriate tooling
(e.g. `git filter-repo` or BFG), re-run secret scanning, and verify the
remote history before resuming any further push. "Delete the file and
commit again" is explicitly insufficient — see
[`RESPONSIBLE_AI.md`](RESPONSIBLE_AI.md) for the broader security-over-
autonomy principle applied throughout this project's development.
