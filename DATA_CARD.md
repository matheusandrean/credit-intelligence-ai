# Data Card — Credit Intelligence AI Synthetic Portfolio

Following the spirit of [Datasheets for Datasets](https://arxiv.org/abs/1803.09010),
adapted for a synthetic credit-risk demonstration dataset.

## Motivation

**Why was this dataset created?** To power a portfolio project demonstrating
a full Credit Intelligence platform (data engineering, credit risk modeling,
explainable AI, generative AI) without any real personal or financial data.

**Who created it?** Generated programmatically by
`src/data/generate_synthetic_credit_data.py`, authored by Matheus Marcondes
for this project.

## Composition

- **100,000 synthetic customers**, one row each, in
  `data/raw/customer_portfolio.parquet` (31 columns — see
  [`FEATURE_DICTIONARY.md`](FEATURE_DICTIONARY.md)).
- **1,542,441 customer-month rows** in
  `data/raw/monthly_performance.parquet`, capturing a delinquency-bucket
  trajectory per account (capped at 18 months of history) for vintage/MOB
  and roll-rate analytics.
- Every customer is entirely fictitious. IDs are sequential
  (`CUST_000001`...`CUST_100000`) and carry no real-world meaning.
- No protected/sensitive characteristics exist anywhere in the schema (see
  `src/data/schema.py::PROHIBITED_PROTECTED_ATTRIBUTES`), and this is
  enforced by an automated data-quality check
  (`src/data/validation.py`), not just a generation-time promise.

## Collection process

There is no "collection" — every row is generated by
`generate_customer_snapshot()` and `generate_monthly_performance_panel()`
using `numpy`'s pseudo-random number generator with a fixed seed (`42`),
so the dataset is exactly reproducible. Statistical relationships between
risk drivers and the target are built deliberately (see below); they are
not copied or derived from any real dataset, institution, or individual.

## Realism design choices

- **Default rate**: calibrated to ≈7.5% portfolio-wide (auto-solved
  intercept), in line with typical unsecured consumer-credit portfolios.
- **Monotonic risk relationships**: default rate rises monotonically with
  DTI quartile (observed: 0.96% → 3.48% → 7.23% → 18.3% from lowest to
  highest quartile), and likewise with credit utilization, late payments,
  and previous default flag — enforced by automated monotonicity checks in
  `tests/unit/test_generate_synthetic_data.py`.
- **Noise and imperfection**: missing values (2-4% on several fields),
  outliers (0.4-0.6% on income/balance/utilization), and irreducible
  latent noise so the resulting classification problem is realistic
  (out-of-time ROC-AUC ≈0.83-0.85 for the champion model, not an
  implausible ~0.95+).
- **Temporal structure**: `observation_date` spans 2023-01 through
  2025-06; `origination_date` is derived from a gamma-distributed account
  tenure, so the portfolio includes both new and seasoned accounts.
- **Portfolio deterioration narrative**: a slow, deliberate upward drift in
  the underlying latent risk factor over calendar time, so later
  observation periods show mildly worse behavior on average — supporting
  the demonstration's monitoring/drift narrative (see
  [`docs/PORTFOLIO_STORY.md`](docs/PORTFOLIO_STORY.md)).

## Uses

**Intended use**: portfolio/educational demonstration of a credit risk +
GenAI platform. **Not intended for**, and must never be used for: real
credit decisions, training a model deployed against real customers without
a full re-validation on real data, or any inference about real individuals.

## Distribution

Raw and processed data files are **not committed to the git repository**
(see `.gitignore`) — they are regenerated locally via `make data` /
`make features`. This keeps the repository small and makes explicit that
every recruiter/reviewer runs the exact same generation code rather than
trusting a static file.

## Maintenance

Regenerating with a different `random_seed` or `n_customers` in
`configs/project_config.yaml` produces a new, equally valid synthetic
dataset with the same statistical properties.
